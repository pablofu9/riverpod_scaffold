# Documentation Rules

- Every file created in this project must be well documented.
- Each file should start with a file-level comment describing its purpose and usage.
- All classes, methods, and functions must include DartDoc-style comments explaining their functionality, parameters, and return values if applicable.
- Use clear and concise language to ensure maintainability and ease of understanding for all contributors.
- Every dart file must start with a well-formed file-level comment using the `/* ... */` style (single asterisk), describing its purpose, author (Pablo Fuertes), and usage.
- In file-level comments, each line should start with `*` for normal information or `!` for important/warning linesr.
- In .md files do not start the documentatio with `/* */`
- Do not use the `library` directive in view files.
